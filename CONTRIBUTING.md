# Contributing

Thank you for contributing.

This repository prioritizes reproducibility, traceability, and auditability over feature volume.

## Contribution types

Contributions are welcome for:

- documentation improvements;
- baseline control mappings;
- PowerShell assertion improvements;
- evidence-generation workflows;
- GitHub Actions;
- reproducibility enhancements;
- review corrections.

## Pull request expectations

A pull request should:

1. describe the purpose of the change;
2. explain any security impact;
3. preserve or improve traceability;
4. avoid introducing sensitive information;
5. keep documentation aligned with the implemented scripts and workflows.

## Documentation standards

Documentation should:

- distinguish implemented behavior from planned behavior;
- avoid unsupported security claims;
- reference implemented controls and baseline versions;
- use consistent terminology.

## Evidence changes

When modifying evidence generation or validation:

- update the relevant documentation;
- update control mappings if identifiers change;
- ensure examples remain reproducible.

## Code style

Favor readability, deterministic behavior, and explicit security assumptions over clever implementations.

## Licensing

By contributing, you agree that your contribution may be distributed under the repository license.
